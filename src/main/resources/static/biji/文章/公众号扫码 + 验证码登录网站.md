# 公众号扫码 + 验证码登录网站 完整实现流程

这是一套**个人 / 订阅号就能实现、无需微信认证**的登录方案，完全匹配你截图中的交互效果：用户扫码关注公众号 → 回复验证码 → 网页端输入完成登录。

## 一、前期准备（必须项）

### 1. 公众号基础配置

1. 准备一个**已认证 / 未认证的公众号（订阅号 / 服务号均可）**，个人订阅号也能实现；

2. 公众号后台开启【开发者模式】，配置：

   - 服务器地址（URL）：你的后端公网地址（需 HTTPS，可使用内网穿透临时测试）
   - Token：自定义的验证字符串
   - EncodingAESKey：随机生成或自动生成

   

3. 申请公众号 AppID 和 AppSecret（公众号后台 → 开发 → 基本配置）

### 2. 技术环境准备

- 后端服务（Java/Node.js/PHP 等均可，需要支持接收微信回调消息）
- 缓存服务（Redis 最佳，用于存储验证码和用户绑定关系，设置 100 秒过期）
- 公网 HTTPS 域名 / 内网穿透工具（如 ngrok，用于本地开发测试）

------

## 二、完整业务流程（分阶段拆解）

### 阶段 1：网页端登录页面初始化

1. 用户访问网站登录页，前端向后端请求登录接口；
2. 后端生成一个**唯一的登录会话 ID（Ticket）**，并生成对应的公众号二维码（可以是公众号普通二维码，也可以是带参数的场景二维码）；
3. 后端将 `Ticket` 存入 Redis，设置过期时间（如 100 秒），并返回给前端；
4. 前端展示：公众号二维码 + 验证码输入框 + 提示文字（“扫码关注公众号，回复验证码登录”），并同步显示验证码倒计时。

### 阶段 2：用户扫码并回复验证码

<img src="C:\Users\DELL\Desktop\图片\阶段二.png" style="zoom:200%;" />

1. 用户用微信扫描网页上的公众号二维码，关注公众号（若已关注则直接进入对话页）；

2. 用户在公众号对话框，发送网页上提示的验证码（如截图中的`229278`）；

3. 微信服务器将用户的文本消息，推送到你配置的后端回调 URL；

4. 后端接收微信回调消息，解析关键信息：

   - `FromUserName`：用户的微信 OpenID（唯一标识，后续绑定用户用）
   - `Content`：用户发送的验证码内容

   

5. 后端验证逻辑：

   - 校验验证码是否存在于 Redis 中；
   - 校验验证码是否未过期；
   - 校验验证码对应的会话状态是否有效；

   

6. 验证通过后，后端：

   - 将 `验证码` 与 `用户OpenID` 绑定存入 Redis；
   - 给公众号用户回复 “验证成功，请返回网页完成登录”；
   - 标记该验证码状态为 “已绑定用户”。

   

### 阶段 3：网页端验证并完成登录

1. 用户在网页输入框中，输入公众号回复的验证码（或直接输入网页上展示的验证码）；

2. 前端将验证码发送给后端的登录验证接口；

3. 后端验证逻辑：

   - 校验验证码是否存在、是否过期；
   - 校验验证码是否已绑定用户 OpenID；
   - 校验会话 ID 是否匹配（可选，增强安全性）；

   

4. 验证通过后，后端：

   - 根据 OpenID 查询 / 创建用户账号（首次登录自动注册）；
   - 生成网站登录态 Token（如 JWT/Session）；
   - 清除 Redis 中该验证码的绑定关系；
   - 返回登录成功响应，携带 Token；

   

5. 前端接收 Token，存入本地存储，跳转至网站首页，完成登录。

# 优化

公众号回复增加 “验证码无效”“验证成功” 的明确提示； 首次登录自动创建用户账号，无需额外注册流程；
