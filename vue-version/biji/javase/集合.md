# Collection

## 1.架构

### 集合整体架构

**Java 集合架构（Java Collections Framework, JCF）**

Java 集合是**存储对象数据的容器**，用来替代传统数组（数组长度固定、操作不便），提供动态扩容、丰富的 API 和高效的增删改查。

整个集合架构围绕**接口、抽象类、实现类**三层设计，核心分为两大体系：

集合两大根接口：

1. Collection

   ：单列集合（单个元素存）

   - List（可重复、有索引、有序）
   - Set（不可重复、无索引）
   - Queue（队列）

2. **Map**：双列集合（键值对 key-value）

整体层级：

- Collection → List：ArrayList、LinkedList、Vector
- Collection → Set：HashSet、LinkedHashSet、TreeSet
- Map：HashMap、LinkedHashMap、TreeMap、Hashtable、Properties

```
┌── Collection（根接口，单值集合）
│   ├── List（有序、可重复、支持索引）
│   │   ├─ ArrayList（动态数组）
│   │   ├─ LinkedList（双向链表）
│   │   └─ Vector（线程安全，已淘汰）
│   │
│   ├── Set（无序、不可重复）
│   │   ├─ HashSet（哈希表，无序）
│   │   ├─ LinkedHashSet（哈希+链表，有序）
│   │   └─ TreeSet（红黑树，可排序）
│   │

│       ├─ LinkedList（双端队列）
│       └─ PriorityQueue（优先级队列）

└── Map（根接口，键值对集合）
    ├── HashMap（哈希表，无序）
    ├── LinkedHashMap（哈希+链表，有序）
    ├── TreeMap（红黑树，可排序）
    ├── Hashtable（线程安全，已淘汰）
    └── ConcurrentHashMap（线程安全，推荐使用）
```

## 4.迭代器

**迭代器（Iterator）：是 Java 用来统一遍历所有单列集合的专用工具。**

就是集合的**专属遍历器**，不管是 List 还是 Set，都能用迭代器挨个取出元素。

迭代器是集合通用遍历工具，hasNext 判有无，next 取元素，遍历中不能用集合增删，否则报并发修改异常。

### 1.迭代器基本使用

```
1.概述:Iterator接口
2.主要作用:遍历集合
3.获取:Collection中的方法:
  Iterator<E> iterator()
4.方法:
  boolean hasNext()  -> 判断集合中有没有下一个元素
  E next()  ->获取下一个元素    
```

### 2.为什么要有迭代器

1. List 有索引可以用普通 for 遍历，但**Set 没有索引**，没法用普通 for；
2. Java 需要**统一一种遍历方式**，适配所有 Collection 集合；
3. 隐藏集合底层结构（数组 / 链表 / 哈希表），不用关心底层，直接遍历。

### 3.迭代器三大核心方法

1. hasNext()判断下一个有没有元素，返回 boolean，有就 true，没有 false。
2. next()取出下一个元素，并指针后移。
3. remove()删除当前遍历到的元素。

private class Itr implements Iterator<E> {
        int cursor;       // index of next element to return
        int lastRet = -1; // index of last element returned; -1 if no such
    
        /*
          modCount: 实际操作次数

        int expectedModCount = modCount;
    
        @SuppressWarnings("unchecked")
        public E next() {

        final void checkForComodification() {
            if (modCount != expectedModCount)
                throw new ConcurrentModificationException();

### 7.高频面试考点

1. **迭代器原理**

   集合调用`iterator()`生成迭代器，**默认指向第一个元素之前**；

   `hasNext()`判断有无，`next()`取值并移动指针。

2. **并发修改异常 ConcurrentModificationException**

   遍历集合时，**不能用集合对象直接增删元素**，会报异常；

   只能用**迭代器自己的 remove ()** 方法删除。

3. 增强 for 循环底层

   **增强 for 循环本质就是迭代器**，语法简化而已。

4. 迭代器特点

- 只能**单向遍历**（从头到尾，不能回头）
- 只能遍历，不能直接修改元素，只能用自带 remove
- 所有单列集合通用

public E get(int index) {
    checkElementIndex(index);
    return node(index).item;

Node<E> node(int index) {
    // assert isElementIndex(index);

    if (index < (size >> 1)) {
        Node<E> x = first;
        for (int i = 0; i < index; i++)
            x = x.next;
        return x;
    } else {
        Node<E> x = last;
        for (int i = size - 1; i > index; i--)
            x = x.prev;
        return x;
    }
}
```

```java
index < (size >> 1)采用二分思想，先将index与长度size的一半比较，如果index<size/2，就只从位置0往后遍历到位置index处，而如果index>size/2，就只从位置size往前遍历到位置index处。这样可以减少一部分不必要的遍历

## 9.Queue 接口

`Queue` 是 **Collection 子接口**，专门用于**队列场景**，遵循 **FIFO（先进先出）** 规则：**先插入的元素，最先取出**。

它的核心作用：**存储待处理的任务、消息、请求**，按顺序排队处理。

**特点**：**先进先出（FIFO）**，多用于队列、缓存。

- `LinkedList`：双端队列，两端都可增删
- `PriorityQueue`：按优先级出队，而非插入顺序

### 1Queue 接口核心特点

1. **继承自 Collection**，拥有增删查等基础方法
2. **典型规则：FIFO（先进先出）**
3. 一般**允许 null**（部分实现不允许，如 `PriorityQueue`）
4. 提供**两套操作方法**：**抛异常** / **返回特殊值**

------

### 2Queue 必背 6 个方法（两套）

|     操作     |   抛异常    | 返回特殊值（推荐） |
| :----------: | :---------: | :----------------: |
| **添加元素** |  `add(e)`   |     `offer(e)`     |
| **查看队首** | `element()` |      `peek()`      |
| **删除队首** | `remove()`  |      `poll()`      |

- **抛异常**：失败直接报错（如队列满了）
- **返回特殊值**：失败返回 `false` / `null`，**更安全，开发首选**

最常用：

- `offer()`：添加
- `poll()`：取并删队首
- `peek()`：只看不删

------

### 3Queue 常用实现类

#### 1. **LinkedList**（最常用）

- 底层：**双向链表**
- 特点：增删极快，查询慢
- 同时实现了 `Queue` 和 `Deque`
- 适用：**普通队列、双端队列**

```
Queue<String> queue = new LinkedList<>();
```

#### 2. **PriorityQueue** 优先级队列

- 底层：**堆（默认小顶堆）**
- 特点：**不按插入顺序，按优先级出队**
- 适用：任务调度、权重排序

```
Queue<Integer> pq = new PriorityQueue<>();
```

#### 3. **ArrayDeque** 数组双端队列

- 底层：**动态数组**
- 特点：效率比 LinkedList 更高
- 适用：高性能队列、栈

```
Queue<String> ad = new ArrayDeque<>();
```

**HashMap vs LinkedHashMap 异同对比表**

**LinkedHashMap 是带顺序的 HashMap**，底层多了双向链表保序，牺牲一点性能和内存，换来有序遍历和 LRU 缓存能力。

| 对比项    | HashMap                         | LinkedHashMap                   |
| --------- | ------------------------------- | ------------------------------- |
| 所属体系  | 实现 Map 接口                   | 实现 Map 接口                   |
| 存储结构  | 键值对 K-V                      | 键值对 K-V                      |
| Key 特性  | 不能重复，重复覆盖              | 不能重复，重复覆盖              |
| Null 支持 | 允许 1 个 null 键、多个 null 值 | 允许 1 个 null 键、多个 null 值 |
| 线程安全  | 非线程安全                      | 非线程安全                      |
| 底层主体  | 哈希表：数组 + 链表 + 红黑树    | 基于 HashMap 扩展，主体结构一致 |
| 遍历方式  | 支持 key/value/entry 遍历       | 支持 key/value/entry 遍历       |

| 对比项       | HashMap                      | LinkedHashMap                          |
| ------------ | ---------------------------- | -------------------------------------- |
| 遍历顺序     | **无序**，和插入顺序无关     | **有序**：默认插入顺序，可开启访问顺序 |
| 底层结构     | 数组 + 链表 + 红黑树         | HashMap + **双向循环链表**维护顺序     |
| 内存占用     | 较小                         | 稍大（多维护一条链表）                 |
| 读写性能     | 更快，无顺序维护开销         | 略慢，要维护双向链表                   |
| 访问顺序机制 | 不支持                       | 支持 LRU 访问顺序（适合做缓存）        |
| 继承关系     | 直接继承 AbstractMap         | **继承 HashMap**                       |
| 适用场景     | 只需要快速存取值、不关心顺序 | 要保持插入顺序、实现 LRU 缓存          |

```java
需求:用Map集合统计字符串中每一个字符出现的次数
步骤:
  1.创建Scanner和HashMap
  2.遍历字符串,将每一个字符获取出来
  3.判断,map中是否包含遍历出来的字符 -> containsKey
  4.如果不包含,证明此字符第一次出现,直接将此字符和1存储到map中
  5.如果包含,根据字符获取对应的value,让value++
  6.将此字符和改变后的value重新保存到map集合中
  7.输出

```java
public class Demo06HashMap {
    public static void main(String[] args) {
        //1.创建Scanner和HashMap
        Scanner sc = new Scanner(System.in);
        HashMap<String, Integer> map = new HashMap<>();
        String data = sc.next();
        //2.遍历字符串,将每一个字符获取出来
        char[] chars = data.toCharArray();
        for (char aChar : chars) {
            String key = aChar+"";
            //3.判断,map中是否包含遍历出来的字符 -> containsKey
            if (!map.containsKey(key)){
            //4.如果不包含,证明此字符第一次出现,直接将此字符和1存储到map中
                map.put(key,1);
            }else{
                //5.如果包含,根据字符获取对应的value,让value++
                //6.将此字符和改变后的value重新保存到map集合中
                Integer value = map.get(key);
                value++;
                map.put(key,value);
            }
        }

        //7.输出
        System.out.println(map);
    }
}

## 5.Properties 集合 

### 一、是什么

`Properties` 是 Java 里**专门用来读配置文件**的集合类。

继承自 **Hashtable**，本质就是一个 **特殊的 Map**。

作用：**存配置、读配置**，比如：

数据库账号密码、网站端口、项目参数、常量配置。

### 二、核心特点

1. 键和值只能是 String 字符串

   不用写泛型，默认都是字符串。

2. 天然支持读写 `.properties` 配置文件，可以把配置保存到文件，也能从文件加载

3. **继承 Hashtable，线程安全**

4. **key 不能重复**，重复会覆盖。

5. 配置文件格式是：`key=value`

### 三、底层关系

plaintext

```
Object
   ↳ Hashtable
       ↳ Properties
```

**本质：就是一个只能存字符串的 Map，自带配置文件读写功能。**

### 四、配置文件长什么样（xxx.properties）

properties

```
# 数据库配置
username=root
password=123456
url=jdbc:mysql://localhost:3306/db
```

### 五、常用核心方法

- `load(流)`：**加载配置文件**
- `getProperty(key)`：根据键**取值**
- `setProperty(key,value)`：设置键值对
- `store(流, 注释)`：把配置**保存到文件**

### 六、简单代码示例

java运行

```
import java.util.Properties;
import java.io.FileReader;

public class Demo {
    public static void main(String[] args) throws Exception {
        // 1. 创建Properties对象
        Properties pro = new Properties();
        
        // 2. 加载配置文件
        pro.load(new FileReader("db.properties"));
        
        // 3. 读取配置
        String user = pro.getProperty("username");
        String pwd = pro.getProperty("password");
        
        System.out.println(user);
        System.out.println(pwd);
    }
}
```

### 七、面试一句话总结

**Properties 是继承 Hashtable 的特殊集合，键值都是字符串，专门用于 Java 读取和写入 properties 配置文件。**

## 2学生成绩管理系统

Java集合综合练习项目——学生成绩管理系统

# 项目说明

本项目是基于Java集合框架（List、Set、Map、Queue）开发的学生成绩管理系统，模拟学校教务系统中对学生、课程、成绩的日常管理操作，包含学生信息管理、课程管理、成绩录入与统计、数据导出、排队查询等核心功能，全面覆盖集合框架的常用API及应用场景，代码量不少于1000行，贴合实际开发逻辑，注释详细，可直接运行。

核心技术点：

- List接口：使用ArrayList存储学生、课程、成绩列表，实现增删改查、排序、筛选功能
- Set接口：使用HashSet实现学生、课程去重（重写equals和hashCode），使用TreeSet实现成绩排序
- Map接口：使用HashMap存储学生ID与学生对象、课程ID与课程对象的映射，使用LinkedHashMap保证数据插入顺序，使用TreeMap实现成绩按分数排序
- Queue接口：使用LinkedList实现学生排队查询成绩，使用PriorityQueue实现成绩优先级排序（按分数从高到低）
- 集合工具类：使用Collections实现排序、反转、查找，使用Arrays实现数组与集合的转换
- 异常处理：自定义异常，处理非法输入、数据不存在等异常场景
- 模块化设计：分为实体层、工具层、业务逻辑层、测试层，降低耦合度

                .mapToDouble(Score::getScore)

     * @return 输入的整数

     */
    public static int readInt(String prompt) {
        System.out.print(prompt);
        try {
            // 读取整数
            return scanner.nextInt();
        } catch (Exception e) {
            // 清除缓冲区，避免死循环
            scanner.nextLine();
            throw new IllegalInputException("输入错误！请输入有效的整数。");
        }
    }

    /**
     * 读取整数输入，并指定范围
     * @param prompt 提示信息

     * @return 范围内的整数
     * @throws IllegalInputException 非法输入异常
     */
    public static int readInt(String prompt, int min, int max) {
        int num = readInt(prompt);
        if (num < min || num > max) {
            throw new IllegalInputException("输入错误！请输入" + min + "~" + max + "之间的整数。");
        }
        return num;
    }

    /**
     * 读取长整数输入
